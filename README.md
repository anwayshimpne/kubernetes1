# Kubernetes Guestbook final project

A small nginx-served guestbook UI, Kubernetes Deployment and Service, and CPU-based Horizontal Pod Autoscaler. The current `index.html` is the v2 page; `versions/v1/index.html` preserves the original page for the first image/revision.

## Build and publish to IBM Cloud Container Registry

Prerequisites: `ibmcloud` and `kubectl` installed, an authenticated IBM Cloud account, a registry namespace, and a Kubernetes cluster with metrics available. Replace `YOUR_NAMESPACE` and the registry region as appropriate. These commands are a guide; this repository does not contain output from a real IBM Cloud account or Kubernetes cluster.

```sh
ibmcloud cr login
ibmcloud cr namespace-list
export REGISTRY=us.icr.io
export NAMESPACE=YOUR_NAMESPACE

docker build -t "$REGISTRY/$NAMESPACE/guestbook:v1" -f Dockerfile .
docker push "$REGISTRY/$NAMESPACE/guestbook:v1"
ibmcloud cr images
```

To build the original v1 page, temporarily use `versions/v1/index.html` as the build context's `index.html` (for example, copy it into a clean build directory with the Dockerfile). Build v2 from the root `index.html`:

```sh
mkdir -p /tmp/guestbook-v1
cp Dockerfile versions/v1/index.html /tmp/guestbook-v1/
docker build -t "$REGISTRY/$NAMESPACE/guestbook:v1" /tmp/guestbook-v1
docker push "$REGISTRY/$NAMESPACE/guestbook:v1"
docker build -t "$REGISTRY/$NAMESPACE/guestbook:v2" .
docker push "$REGISTRY/$NAMESPACE/guestbook:v2"
```

For the Docker push digest evidence, retain the final `docker push` output, including its `digest: sha256:...` line. The digest is generated by the registry and cannot be supplied in advance.

## Deploy and exercise the project

Set the IBM registry namespace in `deployment.yml` before applying it. Authenticate your cluster for registry pulls as needed.

```sh
kubectl apply -f deployment.yml
kubectl apply -f service.yml
kubectl rollout status deployment/guestbook
kubectl get deployment,pods,svc
```

The `deployment.yml` provided here points to v2. To create the v1 starting revision, set its image to `us.icr.io/$NAMESPACE/guestbook:v1` and apply it first. To deploy v2, set it to `us.icr.io/$NAMESPACE/guestbook:v2` and run `kubectl apply -f deployment.yml`; wait for rollout status.

Apply autoscaling after the Deployment exists and has CPU requests (the included manifest sets them):

```sh
kubectl apply -f hpa.yml
kubectl get hpa guestbook --watch
kubectl get deployment guestbook --watch
```

HPA `minReplicas: 1` is intentional: standard CPU-based Kubernetes HPA does not scale a Deployment from zero. The initial zero-replica state, if required by the course's evidence prompt, can be shown by scaling to zero before creating/applying the HPA. Do not expect this CPU HPA to activate from zero; restore at least one replica to test it. CPU scale-up requires metrics-server and enough CPU-consuming workload to exceed the target.

For an optional local load generator, run this from a terminal while the app is deployed (the image must have `busybox`):

```sh
kubectl run guestbook-load --rm -it --restart=Never --image=busybox:1.36 -- /bin/sh -c 'while true; do wget -q -O- http://guestbook/ >/dev/null; done'
```

The static page responds quickly and may not generate enough CPU to trigger HPA; use a course-provided load tool if available. Check `kubectl describe hpa guestbook` for metric and scaling events.

## Rollout, CPU-related revision, and rollback

Capture revision history before and after the CPU/resource change. Change a Pod template field such as the container CPU request in `deployment.yml` (for example, `100m` to `150m`) and apply it to create a new Deployment revision. Restore the desired manifest afterward if appropriate. HPA needs CPU requests to calculate utilization.

```sh
kubectl rollout history deployment/guestbook
# Edit a Pod-template field in deployment.yml, then:
kubectl apply -f deployment.yml
kubectl rollout status deployment/guestbook
kubectl rollout history deployment/guestbook
kubectl rollout undo deployment/guestbook
kubectl rollout status deployment/guestbook
kubectl get rs
```
